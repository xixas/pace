# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Pace puts PineStem billed hours on the Linux panel. It is a personal project: never billed, no Jira or
PineStem task. Start with `README.md`, which covers what Pace is, install, commands, layout and release.

## Commands

| Task | Command |
|---|---|
| Tests | `uv run pytest -q` (a single test: `uv run pytest -q tests/test_engine.py::test_name`) |
| Lint | `uvx ruff check . && uvx ruff format --check .` |
| Extension tests | `gjs -m extension/tests/look.test.js` and `gjs -m extension/tests/widget.test.js` |
| Desktop and AppStream files | `make check` |

CI runs all four on every push to `main`.

## Architecture

paced (`pace/daemon.py`) does all the maths and wording and writes `$XDG_STATE_HOME/pace/status.json`. The
GNOME extension, the tray, the GTK app and the nudges only draw that file. Put verdict logic in
`pace/engine.py`, `pace/targets.py` and `pace/status.py`, never in a frontend. The core never imports GTK;
only `pace/ui/` does.

## Read before changing

- `docs/architecture.md`: how paced, `status.json` and the frontends fit together, plus the rules that
  shape the code.
- `docs/contract.md`: the keys, files and D-Bus members, and who owns which module. When data disagrees,
  the contract wins.
- `docs/design.html`: screens and wording (ids such as B3 and C10 are cited in comments). When look or
  wording disagrees, the design wins.
- `docs/testing.md`: before you call any UI or packaging change done. Unit tests miss empty shell menus and
  widgets that never open.

## Git

- Work on a branch and merge into `main` **fast-forward only** (`git merge --ff-only`). Rebase first when
  needed. Keep the history free of "Merge …" commits, and leave pushed history as it is.
- Push to `origin` (`xixas/pace`, private) without asking. Routine CI, packaging and release work needs no
  go-ahead.

## Gotchas

- GNOME on Wayland loads extension code only at login. paced and the app need only a restart.
- The headless shell harness refuses to run without `PACE_PRIVATE_BUS=1`.
- The KDE container needs `--device /dev/dri/renderD128`, because software KWin segfaults on screenshot.
- `packaging/rpm/pace.spec` is the version source. `pyproject.toml` stays at `0.0.0`, and
  `pace/_version.py` is generated by `make install`.
- `dev/mock_hrms.py` data is personal billing data. Keep snapshots outside the repo.
